# Pothole: notes for Claude

Ad-blocking forwarding DNS server for Windows with a WPF window and tray icon. Started 2026-11-25.

- Target `net8.0-windows`, WPF + WinForms (tray icon only; WinForms/Drawing implicit usings removed in the csproj). Project in `src\Pothole`.
- Close the running copy (`Pothole.exe --exit`) before `publish.ps1`: the root exe is locked while it runs, so the copy there fails after the version is already archived (happened with 0.2.0; finish by copying `dist\Pothole.exe` to the root).
- `.\publish.ps1` → self-contained single file `Pothole.exe` at the root plus `Versions\Archive\Pothole-<version>.exe`; refuses an archived version. Bump `<Version>` in the csproj first, then commit, push, `gh release create v<version> Pothole.exe`.
- Data in `Pothole-Data\` next to the exe (settings.json, stats.json, lists\ cache, logs\). Env `POTHOLE_DATA=<dir>` overrides it: use a scratchpad folder for tests.
- Engine: `DnsServer.cs` forwards raw packets to the upstreams (UDP, TCP for TCP clients), answers blocked A/AAAA with 0.0.0.0/:: and other types with an empty answer. `Filter.cs` matches a name and all its parents; Allowed beats everything. No cache. Listens on IPv4 plus `::1` only (for the PC's own IPv6 DNS setting).
- `PcDns.cs` ("Use on this PC"): elevated PowerShell (UAC each time) sets every present physical adapter to 127.0.0.1 + ::1, saving manually typed servers to `pc-dns-backup.json` first; off resets to automatic and restores them. Scripted `--exit` never asks; tray Exit offers to put DNS back.
- Claude's own commands see a sandboxed copy of HKCU (like `%LocalAppData%`): a test copy started with Start-Process writes only to that copy, and reading the Run key from a Claude command can show stale values. Read the real one from outside with WMI `Win32_Process` Create running `reg query ... > file`, and start test copies that must touch real settings through WMI too.
- On this PC, Windows Internet Connection Sharing (SharedAccess) holds UDP 0.0.0.0:53, so Pothole falls back to binding 127.0.0.1 and each IPv4 address separately (that works).
- **Background testing:** `Pothole.exe --exit` closes a running copy gracefully (saves stats). Start a test copy with env `POTHOLE_DATA=<scratch>` and `--test --tray`; a second plain launch shows the window off-screen without activating it. Query it with `Resolve-DnsName <name> -Server 127.0.0.1 -DnsOnly` (add `-TcpOnly` for TCP). Capture with `PrintWindow(hwnd, hdc, 2)`. Never switch tabs with UIA `SelectionItemPattern.Select`: on 2026-11-25 that activated the test window and took the owner's focus.
- **Real-input testing (owner away):** UIA DataItem for Activity/Block-list rows, ListItem for the Allow/Block lists; WPF title-bar buttons aren't in UIA, so close with Alt+F4. Two buttons share each name ("Add", "Remove selected"): pick by X against the list's rect. The tray icon sits in the hidden-icons overflow of the owner's auto-hide StartIsBack taskbar, which UIA can't see and which toggles unpredictably: clicks there landed on other apps on 2026-11-25, so the tray menu is still untested with real input; ask the owner to try it instead.
- Icon `src\Pothole\Pothole.ico` was drawn once with System.Drawing (road square, pothole, red slash); redraw it the same way if it needs to change.
